# 2026-07-08-admin — CMS админка v1

## Запрос пользователя

> «Так, админка должна быть максимально простой, быстрой, с быстрым редактированием текста в секциях и добавлением новых секций, их вариаций. Решение подбери сам. Главное, чтобы был админ UI и быстрота внедрения. Чтобы картинки можно было загружать и редактировать текст. Планируй внедрение админки под текущую кодовою базу. И внедряй. После создадим тестовое наполнение и будем писать e2e тесты»

## Принятое решение

**Гибрид: file-based markdown + custom Nitro admin UI**

Почему:
- ✅ Скорость внедрения — никаких внешних сервисов
- ✅ Vendor-free — markdown в git, версионируется
- ✅ Простой UI на тех же Vue-компонентах
- ✅ Картинки загружаются в `public/uploads/` (git-ignored)
- ✅ E2E тесты Playwright смогут покрыть и админку, и публичную часть

## Что было испробовано

1. ❌ `@nuxt/content@3.15.0` — требует `better-sqlite3` (native compilation, prompts в TTY). Отказался.
2. ✅ **`gray-matter@4.0.3`** (4 KB, zero-deps) + custom `loadSiteContent()` — читает markdown напрямую через `fs.readdir` + `fs.readFile` + `matter()`.

## Архитектура

```
content/                          # ← markdown файлы (в git)
  hero.md
  about.md
  workflow.md
  services.md
  contact.md
  header.md
  portfolio/
    case-slug.md                  # один файл на кейс (slug-based, удобно редактировать)

public/uploads/                   # ← загруженные картинки (git-ignored)
  hero/...
  portfolio/case-slug/...

app/
  composables/
    useSiteContent.ts             # loadSiteContent() + useSiteContent()
  pages/
    index.vue                     # useSiteContent() → передаёт siteContent в секции
    admin/
      login.vue                   # форма входа
      index.vue                   # sidebar + 6 секций (header/hero/about/workflow/services/contact)
      portfolio.vue               # CRUD кейсов

app/components/admin/
  AdminSection.vue                # обёртка с кнопкой «Сохранить»
  AdminAssetInput.vue             # upload image + alt + URL
  AdminHeader.vue                 # форма для header
  AdminHero.vue                   # форма для hero
  AdminAbout.vue                  # форма для about (с tools list)
  AdminWorkflow.vue               # форма для workflow (с steps list, ↑↓)
  AdminServices.vue               # форма для services (с items list, ↑↓)
  AdminContact.vue                # форма для contact (с socials list)
  AdminPortfolioForm.vue          # форма для кейса (4 типа layout)

server/
  api/
    auth/login.post.ts            # POST { password } → { token }
    content/
      index.get.ts                # GET → SiteContent
      index.put.ts                # PUT { path, data } → save to content/[path].md
      index.delete.ts             # DELETE ?path=...
    upload.post.ts                # POST multipart → /public/uploads/...
    upload.delete.ts              # DELETE ?url=/uploads/...
  utils/
    auth.ts                       # HMAC login/verifyToken
    requireAuth.ts                # guard для admin endpoints

app/middleware/
  admin-auth.ts                   # клиентский: редирект на /admin/login если нет cookie
```

## API контракт

| Endpoint | Метод | Auth | Описание |
|----------|-------|------|----------|
| `/api/auth/login` | POST | ❌ | `{password}` → `{token}` |
| `/api/content` | GET | ❌ | весь SiteContent (для админки) |
| `/api/content` | PUT | ✅ | `{path, data}` → save md |
| `/api/content?path=...` | DELETE | ✅ | удалить md |
| `/api/upload` | POST | ✅ | multipart `{file, section?}` → `{url, filename, size}` |
| `/api/upload?url=...` | DELETE | ✅ | удалить файл |

## Auth

- **Password** из env `ADMIN_PASSWORD` (default: `admin`)
- **HMAC token** с TTL 24 часа, base64 в cookie `admin-token`
- **Middleware** на admin pages — редирект если нет cookie
- **Server guard** `requireAuth(event)` — кидает 401 если токен невалидный

## Lessons learned

- **Nuxt Content v3 тяжёлый** (требует SQLite) — для простого file-based CMS лучше `gray-matter`
- **`useAsyncData` auto-import** не работает в `.ts` composables — нужно `declare function useAsyncData<T>(...)` для типов
- **TS strict mode** ловит массив-через-индекс swap — нужно `!` (non-null) или временную const
- **Inline `@change="(e) => ..."`** в template — TS не выводит тип `e`. Лучше explicit method
- **`requireAuth` middleware** на сервере + client middleware на страницах = double protection
- **Markdown frontmatter** — отличный формат для content management без БД. Git-friendly, читаемый, диффы работают
