# layout-absolute-pattern

## Текущий подход

Каждая секция (Header, About, Workflow, Services, Portfolio, ContactSection, PortfolioCaseN) использует **absolute positioning** с захардкоженными px-координатами.

### Пример (About.vue, scss)

```scss
.about {
  &__content { position: relative; height: 832px; }

  &__intro {     position: absolute; top: 28px;  left: 17px; right: 17px; }
  &__title {     position: absolute; top: 240px; right: 0; }
  &__photo {     position: absolute; top: 249px; left: 640px; }
  &__decorative--print    { position: absolute; top: 164px; }
  &__decorative--digital  { position: absolute; top: 618px; }
  &__tools {     position: absolute; top: 255px; left: 119px; width: 378px; }
  &__outro {     position: absolute; bottom: 36px; }
}
```

Все размеры `height: 832px` → взяты **из дизайн-макета Figma** (заказчика).

## Почему так

1. **Дизайн-макет — пиксель-перфект** (1280×832). Разработчик (вероятно, AI-агент) сверял каждый элемент по координатам.
2. **Не было итераций** — никто не рефакторил layout после первой вёрстки.
3. **БЭМ-классы + absolute = просто описать координаты** для одной сцены.

## Последствия

### ❌ Что ломается

| Проблема | Где видно |
|----------|-----------|
| Высота 832px не масштабируется — на 4K выглядит «коротко» | Desktop ≥ 2xl |
| На tablet (900-1024) пересечения элементов, overflow | About, Services |
| Hero `top: -100px` — уродливый хак | Hero.vue:35 |
| Контент может налезать на другие блоки | Workflow mobile |
| `position: absolute` + адаптив → нужны отдельные @media с новыми координатами для каждого breakpoint'а (что и сделано — но много дублей) | Все компоненты |
| Невозможно добавить контент динамически | Services, кейсы |

### ❌ Что мешает админке

- **Контент захардкожен в `<template>`** — невозможно редактировать без перекомпиляции
- **Размеры в px** — нельзя «растянуть» секцию под длинный текст
- **Нет data-driven подхода** — каждый кейс это **отдельный .vue файл**

## Альтернативы (для будущего)

### Вариант A: CSS Grid

```scss
.about {
  display: grid;
  grid-template-areas:
    "intro     intro"
    "title     photo"
    "tools     photo"
    "decorative decorative"
    "outro     outro";
  gap: 2rem;
}
```

✅ Адаптивно, расширяемо, читаемо.
❌ Нужно переработать каждый компонент.

### Вариант B: Flex column

```scss
.about { display: flex; flex-direction: column; gap: 4rem; }
```

✅ Очень просто, семантично.
❌ Теряются 2-колоночные композиции (About, Services).

### Вариант C: Оставить absolute, но вынести координаты в токены

```scss
$about-title-top: 240px;
$about-photo-top: 249px;
```

✅ Меньше боли, но это всё ещё absolute.

## Рекомендация

**Для админки — Вариант A (CSS Grid)** обязателен. Иначе контент-менеджер не сможет:
- Добавить новый кейс (нужно создать новый .vue)
- Изменить порядок блоков внутри кейса
- Вставить длинный текст (абсолютно спозиционированный контейнер не расширится)

**До админки** — можно оставить как есть, если:
- Правки вёрстки только «по дизайн-макету» (фиксы багов, точечные изменения)
- Не предвидится добавление контента
